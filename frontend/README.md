# PiLambdaChart — Web Frontend

## IoT Telemetry Dashboard
Dark-slate static dashboard visualising multi-device, multi-metric IoT telemetry charts generated by backend Lambda functions or the developer CLI.

## Folder Structure

*   `public/index.html`: Semantic HTML5 dashboard — sidebar navigation, topbar controls, data source badge, date headers, chart grid, and chart lightbox modal.
*   `public/style.css`: Modern HSL dark-slate design system featuring glassmorphism cards, sticky date dividers (`position: sticky`), responsive grid layouts, and crosshair overlay styles.
*   `public/app.js`: Dynamic frontend application — loads `file-list.json` and `metadata.json`, initializes `METRIC_META` dynamically from DynamoDB metadata exports, manages device & year/month navigation, renders chart grids, and drives synchronized crosshair tracking and lightbox modals.
*   `public/output/`: Generated chart PNG assets, `.json` sidecars, `file-list.json`, and `metadata.json`.
    *   Populated locally by the **Chart Generator CLI** (`backend/lambda/ChartGeneratorCLI.java`).
    *   In production, written to S3 by the **Chart Generator Lambda** (`backend/lambda/ChartGeneratorHandler.java`).
    *   Structure: `output/{deviceId}/{metricId}/{year}/{month}/{metricId}-YYYYMMDD.png` (+ `{metricId}-YYYYMMDD.json` sidecar)
    *   Catalog: `output/file-list.json` — hierarchical Device → Metric → Year → Month → Files index.
    *   Registry: `output/metadata.json` — exported metric & device metadata (names, units, icons, minimum Y-axis ranges).
*   `deploy.sh`: AWS CLI script to sync static assets and optional chart output files (`--include-output`) to S3 with cache headers.

---

## Key Dashboard Features

1. **Dynamic Metadata & Configurable Icons**:
   - Metric definitions (names, units, chart types, emoji icons, minimum Y-axis ranges) are populated dynamically from `metadata.json` and chart sidecars. No hardcoded metric maps in `app.js`.

2. **Synchronized Crosshairs & Data Tooltips**:
   - Hovering over any chart displays a synchronized crosshair line and accurate data tooltip snapped across all metric charts for that day.

3. **Sub-Pixel Data Alignment**:
   - Uses exact chart plot area boundaries from `.json` sidecars for sub-pixel crosshair position accuracy.

4. **Sticky Date Headers**:
   - Date headers stick cleanly below the topbar (`position: sticky; top: var(--topbar-height)`) with glassmorphism backdrop blur (`backdrop-filter: blur(12px)`).

## Local Development

The dashboard works directly with standard static HTTP servers — no Node build step or bundler required.

### Prerequisites

Generate chart assets locally using the CLI:

```bash
cd backend/lambda
mvn compile exec:java -Dexec.args="-d 1 -m 1,2,3,4,5"
# Charts, sidecars, file-list.json, and metadata.json are saved to frontend/public/output/
```

### Run Locally

**Option A — Python HTTP server** (recommended):

```bash
cd frontend/public
python3 -m http.server 8080
# Open http://localhost:8080
```

**Option B — VS Code Live Server**: Right-click `index.html` → Open with Live Server.

> **Note:** Opening `index.html` directly as `file://` will fail because browser CORS policy blocks `fetch()` calls for local JSON files. Use a local HTTP server.

## Deploying to S3

### 1. Configure S3 Static Website Hosting

```bash
aws s3 website s3://your-bucket-name \
  --index-document index.html \
  --error-document index.html
```

Or manage it declaratively via Terraform in `infrastructure/`.

### 2. Set Production Data URL in `index.html` (Optional)

Add a `<meta>` tag pointing to the S3/CloudFront URL where chart assets live:

```html
<!-- In index.html <head>, before <link rel="stylesheet"> -->
<meta name="data-base-url" content="https://your-bucket.s3.amazonaws.com/output" />
```

Or set a global variable before `app.js` loads:

```html
<script>window.PILAMBDACHART_BASE_URL = 'https://d123example.cloudfront.net/output';</script>
```

> Leave both unset to use the default `output` relative path (local dev mode).

### 3. Run the Deploy Script

```bash
cd frontend/

# Deploy frontend static assets (HTML, CSS, JS)
./deploy.sh --bucket your-bucket-name

# Deploy frontend static assets AND output PNG/JSON chart files
./deploy.sh --bucket your-bucket-name --include-output

# Deploy with CloudFront cache invalidation
./deploy.sh --bucket your-bucket-name --cloudfront E1ABCDEF123456 --include-output

# Dry run (preview upload actions without executing)
./deploy.sh --bucket your-bucket-name --dry-run
```

### Cache-Control Policy

| File | Cache-Control Header |
|:---|:---|
| `index.html` | `no-cache, no-store, must-revalidate` |
| `output/file-list.json` & `output/metadata.json` | `public, max-age=60` |
| `output/*.png` & `output/*.json` sidecars | `public, max-age=3600` |
| `*.css`, `*.js` static assets | `public, max-age=31536000, immutable` |

## Architecture Summary

| Aspect | Local Development | Production (AWS) |
|:---|:---|:---|
| Chart Images & Sidecars | `public/output/*` (CLI) | `s3://bucket/output/*` (Lambda) |
| `file-list.json` & `metadata.json` | `public/output/` (CLI) | `s3://bucket/output/` (Lambda) |
| Data Base URL | `output` (relative) | CloudFront/S3 URL via `<meta>` tag |
| Hosting | `python3 -m http.server` | S3 Static Site + CloudFront CDN |
