# PiLambdaChart — IoT Telemetry Dashboard

Premium dark-slate static dashboard that visualises multi-device, multi-metric IoT telemetry charts generated by the backend Lambda function.

## Folder Structure

*   `public/index.html`: Semantic HTML5 dashboard — sidebar, topbar, KPI strip, chart viewer, date rail.
*   `public/style.css`: HSL dark-slate design system with glassmorphism cards and micro-animations.
*   `public/app.js`: Loads `file-list.json`, builds the device → metric tree, renders charts, handles navigation.
*   `public/output/`: Generated chart PNG assets and `file-list.json` index.
    *   Populated locally by the **Chart Generator CLI** (`backend/lambda/ChartGeneratorCLI.java`).
    *   In production, written to S3 by the **Chart Generator Lambda** (`backend/lambda/ChartGeneratorHandler.java`).
    *   Structure: `output/{deviceId}/{metricId}/{year}/{month}/{metricId}-YYYYMMDD.png`
    *   Index: `output/file-list.json` — hierarchical Device → Metric → Year → Month → Files tree.
*   `deploy.sh`: AWS CLI script to sync assets to an S3 static website bucket with correct cache headers.

## Local Development

The dashboard works entirely from the local filesystem — no build step, no bundler.

### Prerequisites

Generate chart PNGs first using the CLI:

```bash
cd backend/lambda
mvn compile exec:java -Dexec.args="-d 1 -m 1,2,3"
# Charts are written to frontend/public/output/ automatically
```

### Run locally

**Option A — Python HTTP server** (recommended, avoids CORS issues with `fetch`):

```bash
cd frontend/public
python3 -m http.server 8080
# Open http://localhost:8080
```

**Option B — VS Code Live Server**: Right-click `index.html` → Open with Live Server.

> **Note:** Opening `index.html` directly as `file://` will fail because `fetch()` is blocked for local files in most browsers. Use a local HTTP server.

## Deploying to S3

### 1. Enable static website hosting on your S3 bucket

```bash
aws s3 website s3://your-bucket-name \
  --index-document index.html \
  --error-document index.html
```

Or configure it via Terraform using the `infrastructure/` files in this repo.

### 2. Set the production data URL in `index.html`

Add a `<meta>` tag pointing to the S3/CloudFront URL where chart assets live:

```html
<!-- In index.html <head>, before <link rel="stylesheet"> -->
<meta name="data-base-url" content="https://your-bucket.s3-website-us-east-1.amazonaws.com/output" />
```

Or set a global variable before `app.js` loads:

```html
<script>window.PILAMBDACHART_BASE_URL = 'https://d123example.cloudfront.net/output';</script>
```

> Leave both unset to use the default `output` relative path (local dev mode).

### 3. Run the deploy script

```bash
cd frontend/

# Basic deploy
./deploy.sh --bucket your-bucket-name

# With CloudFront cache invalidation
./deploy.sh --bucket your-bucket-name --cloudfront E1ABCDEF123456

# Dry run (preview what would be uploaded)
./deploy.sh --bucket your-bucket-name --dry-run

# Using environment variables
S3_BUCKET=your-bucket-name CF_DIST_ID=E1ABCDEF ./deploy.sh
```

The script applies cache-control headers per file type:

| File | Cache-Control |
|:---|:---|
| `index.html` | `no-cache` — always fetch latest |
| `output/file-list.json` | `max-age=60` — refresh within 1 minute |
| `output/*.png` chart images | `max-age=3600` — cache for 1 hour |
| `*.css`, `*.js` static assets | `max-age=31536000, immutable` — cache for 1 year |

## Architecture: Local vs Production

| Concern | Local Development | Production (AWS) |
|:---|:---|:---|
| Chart images | `public/output/*.png` (CLI-generated) | `s3://bucket/output/*.png` (Lambda-generated) |
| `file-list.json` | `public/output/file-list.json` (CLI) | `s3://bucket/output/file-list.json` (Lambda) |
| `app.js` base URL | `output` (relative) | CloudFront/S3 URL via `<meta>` tag |
| Hosting | `python3 -m http.server` | S3 static website + CloudFront CDN |
